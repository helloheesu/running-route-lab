# 클론 후 실행 가이드

이 문서는 사람이 지시를 보완하지 않아도 AI가 실행할 수 있도록 작성했습니다. 모든 명령은 **저장소 루트** 기준입니다. 개인 컴퓨터 경로나 숨겨진 기존 프로젝트가 필요하지 않습니다.

## 기본 실행

1. `node --version`이 24.x인지 확인합니다. `.nvmrc`를 지원하는 환경에서는 `nvm install` 후 `nvm use`를 사용할 수 있습니다. Node 설치 도구 자체는 저장소가 제공하지 않습니다.
npm 캐시는 저장소의 무시되는 `work/npm-cache/`를 사용합니다. 개인 전역 캐시 권한을 변경할 필요가 없습니다.

2. `npm ci`: 잠금 파일대로 의존성을 설치합니다. Python과 클라우드 계정은 필요하지 않습니다.
3. `npm test`: 추천·통합·뒤로가기·지역 범위·개인정보 정리·다운로드 실패 처리를 검사합니다.
4. `npm run data:check`: 포항 지도·지형·예시가 존재하고 금지 메타데이터가 없는지 확인합니다. 광역 파일이 없어도 `Sample-only mode`는 정상입니다.
5. `npm run build`: 타입 검사와 프런트엔드 빌드. `dist/client/index.html`이 있어야 합니다.
6. `npm run dev -- --host 127.0.0.1 --port 4190 --strictPort`: 개발 서버. 표시된 주소로 접속합니다. 종료는 이 프로세스에 Ctrl-C를 보냅니다.

빌드 결과 확인은 `npm run preview -- --host 127.0.0.1 --port 4191 --strictPort`로 합니다. `index.html`을 파일 탐색기에서 직접 열지 마세요. 브라우저 Worker와 자료 URL은 HTTP 서버를 전제로 합니다.

## 실제 동작의 성공 기준

- 처음 화면에 포항 샘플 제공 안내가 나옵니다.
- POSTECH 주변을 선택하고 길 보정 표시를 확인한 후 출발을 확정합니다.
- 기본 5km로 계산해 실제 코스 카드와 지도 경로가 나오는지 확인합니다. 정보가 부족한 추천 기준은 보류될 수 있습니다.
- `?case=postech-5k&variant=B`는 고정 UI 예시입니다. 예시가 보인다고 실제 계산까지 검증된 것은 아닙니다.
- 앱 뒤로가기와 브라우저 뒤로가기가 정상인지 확인합니다. 창 폭 393px에서도 화면과 카드가 잘리는지 확인합니다.

실제 iPhone GPS·Safari 실기기·현장 통행 상태는 별도로 검증해야 합니다. 브라우저 자동 검증이 없는 환경은 실행/화면 확인을 미검증으로 보고합니다.

## 광역 데이터는 선택 사항

```sh
npm run data:regions
npm run data:check
```

첫 준비에는 인터넷과 약 141MB 원본 전송이 필요하며 캐시·준비 디렉터리를 위해 최소 500MB 여유 공간을 권장합니다. 전체가 완료된 후 manifest가 반영됩니다. 개발 서버/페이지를 다시 시작하고, 배포용 정적 결과가 필요하면 다시 빌드합니다. 이후 같은 버전의 완성 자료는 해시를 확인하고 재사용합니다. 포항 출발지여도 긴 목표 거리로 샘플 영역을 벗어나는 자료가 필요하면 광역 준비가 필요합니다.

- 다운로드 오류: 인터넷·원본 응답을 확인하고 같은 명령을 재실행합니다. 최신 자료를 임의로 섞거나 해시 검증을 끄지 마세요.
- 해시 불일치/원본 404: docs/DATA.md의 재생성 절차를 사용합니다. 기본 샘플 실행은 가능합니다.
- 강제 종료 뒤 `.lock` 오류: 먼저 다른 준비 프로세스가 실행 중인지 확인합니다. 없는 경우에만 `public/map-regions.lock/`을 제거한 후 재시도합니다. `public/.regions-staging-*`는 미완성 임시 폴더이고, 앱의 완성 데이터가 아닙니다.
- `public/map-regions.previous/`가 남은 경우: 마지막 폴더 교체 도중 중단됐을 수 있습니다. 현재 폴더를 `npm run data:check`로 검사합니다. 유효한 현재 폴더가 있으면 previous를 제거할 수 있습니다. 현재 폴더가 없으면 previous를 map-regions로 복원하고 다시 검사합니다. 두 폴더가 모두 손상됐으면 보관 위치로 옮기고 재준비합니다.
- 수정한 소스 목록/정리 정책은 기존 캐시와 다른 실험입니다. 정책 버전을 올리고 검증 기록을 갱신합니다.

## 흔한 오류

| 현상 | 확인/조치 |
|---|---|
| 설치·TypeScript 실행 오류 | Node 24인지 확인, `npm ci`로 잠금 설치. 무작정 의존성 버전 변경 금지 |
| 4190 사용 중 | 기존 프로세스를 임의 종료하지 말고 다른 포트를 명시하고 사용 주소를 보고 |
| 화면은 뜨지만 포항 지도 실패 | 포함된 map-data/demo 파일 누락 여부와 HTTP 응답 확인, `npm run data:check` |
| 서울 검색은 되지만 계산 안내가 나옴 | 검색과 지도 보유는 별개. 광역 준비를 완료했는지 확인 |
| 광역 준비 완료 후 정적 사이트는 여전히 샘플 | 데이터 추가 후 `npm run build`를 다시 실행 |
| 일부 지점 후보 없음 | 통행 가능한 그래프 연결과 목표 거리를 점검. 서로 가까운 선을 임의로 연결하지 않음 |
| 고저차·신호 최소 추천이 없음 | 자료 결측 여부 확인. 0으로 채우지 않음 |
| 모바일 런타임 무결성 실패 | 잠금 대상 변경을 검토/복구. 잠금 검사를 제거하지 않음 |

`npm run test:runtime`는 별도 Playwright 기반 기존 UI 검사로, 브라우저 설치가 필요합니다. 기본 `npm test`에는 포함되지 않습니다. 기본 빌드에는 클라우드 설정 파일·인증키·배포 작업이 없습니다.
