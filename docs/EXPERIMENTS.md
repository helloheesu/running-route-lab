# 독립 구현과 비교 실험

기존 코스는 정답이 아니라 참고 기준입니다. 다른 구현이 기존 후보와 같은 좌표를 내도록 강제하지 않습니다. 먼저 정책과 입력을 고정하고, 생성 방법과 평가 정책의 변경 효과를 나눕니다.

## 바로 재현

```sh
npm run bench -- --case postech-5k --runs 3
npm run bench -- --case forest-3k --runs 3
npm run bench -- --case postech-no-terrain --runs 3
```

`data/cases.json`에 출발지·거리·계단·고도 사용 여부가 고정되어 있습니다. 출력은 환경과 단계별 시간, 후보 수, 추천 이유, 보류 기준을 포함합니다. 이 도구는 **Node에서 기존 엔진을 실행**합니다. 실제 브라우저 Worker, 네트워크, iPhone을 측정한 결과로 표현하지 마세요. 첫 반복도 OS 파일 캐시가 비어 있다고 보장하지 않습니다.

현재 엔진은 후보 생성 도중 일부 지표도 계산합니다. 따라서 `generateWithInlineEvidence`는 순수 탐색 시간만이 아닙니다. 계측 이름의 경계를 유지하고 다른 구현과 비교할 때 같은 작업량을 맞춥니다.

## 비교 표에 남길 항목

- 입력: 지도 snapshot/hash, 좌표, 목표 거리, 거리 허용폭, 계단/통행 정책, 고도 유무, 탐색 예산/변형 수.
- 환경: 구현 commit, Node/브라우저 버전, 기기/CPU, Worker 사용 여부, 다운로드 및 캐시 상태.
- 정확성: 출발/도착 일치, 그래프 연결, 실제 거리, 통행 제한 준수, 결측 보존. 이것이 먼저 통과해야 합니다.
- 결과: 후보가 없는 사례 비율, 후보 수, 중복/유사성, 실제 거리 오차, 각 기준 우승자·수치·결측/추정 비율.
- 시간: 다운로드/해제/파싱, 그래프 준비, 탐색·지표, 합치기/평가, 선택, 화면 표시. UI 응답 목표 0.3초는 아직 달성 근거가 아닙니다.

여러 반복의 원시값과 중앙값을 보존합니다. 단일 Mac 관찰값으로 휴대폰 성능이나 새 엔진 우월성을 주장하지 않습니다. 같은 품질/조건을 유지한 속도 개선과 탐색량을 줄인 타협을 구분합니다.
